Association Rule Mining via Apriori in WEKA (v3.4.1)

This guide details how to perform Association Rule Mining using the Apriori algorithm in WEKA (v3.4.1) through both the Graphical User Interface (GUI) and the Simple Command Line Interface (CLI).

1. Key Metric Definitions

WEKA evaluates association rules (L ⇒ R) using several quantitative metrics:

Support

The proportion of transactions containing a given itemset. Apriori iteratively steps down support from an Upper Bound (1.0 / 100%) to a Lower Bound (0.1 / 10%) using step decrements (Δ = 0.05).

Lift
Lift = P(L, R) / (P(L) · P(R))

Measures co-occurrence likelihood relative to pure random chance. Values > 1 indicate positive dependence between the antecedent and consequent.

Leverage
Leverage = P(L, R) - (P(L) · P(R))

Measures the proportion of additional cases covering both L and R beyond independent expectations. Target values are > 0.

Conviction
Conviction = (P(L) · P(¬R)) / P(L, ¬R)

Measures the strength of a rule by evaluating the frequency of the right-hand side failing to occur when the left-hand side occurs. Asymmetric metric with no upper bound.

2. Workflow Options

GUI Method (Explorer)

  1. Load Data: Open WEKA Explorer and load preprocessed, discretized data (e.g., bank-data-final.arff).
  2. Select Module: Navigate to the Associate tab (defaults to the Apriori algorithm).
  3. Configure Parameters: Click the command-line options box next to the "Choose" button to set parameters:
    • Metric Type (-T): Set sorting criteria (e.g., set metric to Lift at a minimum threshold of 1.5).
    • Rule Limit (-N): Increase maximum output rules (e.g., change default from 10 to 100).
    • Bounds (-U / -M): Set Upper Bound support to 1.0 and Lower Bound support to 0.1.
  4. Execute & Save: Click Start. Select a run in the Result list panel to view rules, or right-click to save results (e.g., to bank-data-ar1.txt).

CLI Method (Simple CLI)

While the GUI only outputs generated rules, the CLI allows you to extract frequent itemsets directly.

Standard Rule Generation:

java weka.associations.Apriori -N 100 -T 1 -C 1.5 -D 0.05 -U 1.0 -M 0.1 -S -1.0 -t directory-path\bank-data-final.arff

Save Frequent Itemsets (-I flag):

java weka.associations.Apriori -N 100 -T 1 -C 1.5 -D 0.05 -U 1.0 -M 0.1 -S -1.0 -I -t directory-path\bank-data-final.arff

Note: Adding -I outputs all frequent itemsets (L1 through Lk) along with their support counts prior to presenting the final rules.

Association Rules and Frequent Item Analysis

Association rule mining focuses on finding interesting relationships, dependencies, and patterns among large sets of data items [cite: 1].

1. Overview & Core Concepts

  • Item & Itemset: An item is typically an attribute-value pair or simple value . An itemset I is a subset of available items .
  • Transaction: Represented as a pair (TID, itemset), where TID is a unique transaction identifier . Databases often convert categorical attributes into binary flags to process transactions .
  • Association Rule: An implication of the form X ⇒ Y, where X (antecedent) and Y (consequent) are disjoint itemsets, and Y is non-empty .

2. Core Mining Stage & Algorithms

The discovery process consists of two primary stages :

  1. Find all frequent itemsets: Identify itemsets meeting a specified minimum support threshold .
  2. Generate association rules: Derive rules from those frequent itemsets using a minimum confidence threshold .

The Subset Property (Apriori Property)

Every subset of a frequent itemset must also be frequent . If an itemset is infrequent, none of its supersets can be frequent . Association rule mining algorithms rely on this property to prune candidate itemsets during search .

The Apriori Algorithm Process

  • Candidate Generation (Ck): Combines frequent itemsets from the previous level (Lk-1 Join Lk-1) to create k-itemset candidates .
  • Pruning: Prunes candidate itemsets from Ck if any of their (k-1)-subsets are not in Lk-1 .
  • Support Counting: Scans the transaction database to count candidate frequencies and retains those that meet minsup to form Lk .

3. Key Evaluation Measures

Metric Formula / Definition Range / Ideal Interpretation
Support Support(A ⇒ B) = P(A ∩ B) = Count(A ∩ B) / N 0 to 1 Measures how frequently an itemset or rule appears across all transactions .
Confidence Confidence(A ⇒ B) = P(B|A) = Support(A ∩ B) / Support(A) 0 to 1 Conditional probability measuring how often B appears given A .
Lift Lift(A ⇒ B) = P(A ∩ B) / (P(A) · P(B)) 0 to &infty;
( > 1 ideal)		 Ratio of observed co-occurrence to expected co-occurrence if independent . Values > 1 indicate positive correlation .
Leverage Leverage = Support(A ∩ B) - (Support(A) · Support(B)) -0.25 to 0.25
( > 0 ideal)		 Measures the difference between observed occurrence and expected random chance .
Conviction Conviction = (1 - Support(B)) / (1 - Confidence(A ⇒ B)) 0 to &infty;
(Larger ideal)		 Ratio of expected incorrect predictions to observed incorrect predictions .

Other evaluation metrics include Cosine, Correlation (Phi/Chi-square), Kulczynski, Jaccard, and Odds Ratio .

4. Advanced Topics

Multi-Level Association Rules

Items can be structured in concept hierarchies (e.g., Food ⇒ Milk ⇒ 2% Milk) .

  • Uniform Support: Applies the same minimum support threshold across all hierarchy levels . High levels process easily, but lower-level items may fail to meet the threshold .
  • Reduced Support: Uses lower minimum support thresholds for lower hierarchy levels .
  • Redundancy Filtering: Rules can be filtered out as redundant if their support and confidence are close to expected values derived from ancestor rules .

Practical Issues & Applications

  • Data Format: Standard ARFF files can be inefficient for sparse market basket data where most items are absent per transaction .
  • Insignificant Rules: Rules containing redundant subset information (e.g., {pregnant, female} ⇒ oedema vs. {pregnant} ⇒ oedema) are pruned to avoid output overload .
  • Applications: Market basket analysis, medical research (mapping symptom/disease relationships), store layout optimization, and anomaly detection (e.g., WSARE) .

5. Classification vs. Association Rules

  • Classification Rules: Focus on predicting a single target class attribute, evaluated primarily by predictive accuracy .
  • Association Rules: Map relationships across many potential target fields simultaneously, evaluated using Support, Confidence, and Lift .
